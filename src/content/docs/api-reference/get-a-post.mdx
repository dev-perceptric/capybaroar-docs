Returns one post. Use it to see whether a post went out, where it went out, and why a channel failed.

```http
GET https://app.capybaroar.com/api/v1/posts/{id}
```

## Parameters

| Name | In | Type | Required | Description |
| - | - | - | - | - |
| `id` | path | string | Yes | The post's id |

## Request

<Tabs syncKey="lang">
  <TabItem label="curl">

```bash
curl https://app.capybaroar.com/api/v1/posts/9d8c7b6a-5e4f-4a3b-8c2d-1e0f9a8b7c6d \
  -H "Authorization: Bearer cbr_your_key"
```

  </TabItem>
  <TabItem label="JavaScript">

```js
const res = await fetch(`https://app.capybaroar.com/api/v1/posts/${postId}`, {
  headers: { Authorization: `Bearer ${process.env.CAPYBAROAR_KEY}` },
});
const { post } = await res.json();
const failed = post.channels.filter((c) => c.status === "failed");
```

## Reading the result

- **`published`**: open each channel's `url`.
- **`partial`**: some channels have `status: "failed"` and an `error`. Fix what the error says, then make the post again for those channels.
- **`failed`**: nothing went out. A failed post can be changed and scheduled again with [`PATCH`](/api-reference/update-a-post/).
- **`pending`** on a channel with an `error`: Capybaroar is still retrying. It tries up to 6 times, waiting 1, 5, 15, 60 and then 240 minutes. A sign-in problem or a post the network turned down doesn't retry.

A webhook is easier than asking again and again. [`post.published`](/api-reference/webhook-events/#postpublished) and [`post.failed`](/api-reference/webhook-events/#postfailed) tell you the moment each channel is done.

## Errors

| Status | Message | When |
| - | - | - |
| 400 | `id must be an id from this API` | The id isn't a UUID |
| 404 | `Post not found` | There's no such post, or it's in a brand the key can't use |
