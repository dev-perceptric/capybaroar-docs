Makes one post for one or more channels of the same brand. It's a draft unless `mode` says otherwise. The post gets the same checks the calendar runs, so what works here works in the app.

```http
POST https://app.capybaroar.com/api/v1/posts
```

## Body

| Field | Type | Required | Description |
| - | - | - | - |
| `channel_ids` | list | Yes | 1 to 30 channel ids from [`GET /channels`](/api-reference/channels/), all from one brand |
| `text` | string | No | The text every channel shares. Up to 70,000 characters, and each network's own limit applies. |
| `mode` | string | No | `draft` (the default), `schedule`, `now` or `queue` |
| `publish_at` | string | For `draft` and `schedule` | When it goes out, ISO 8601 with an offset, or `"best"` |
| `media_ids` | list | No | Up to 20 file ids from [`GET /media`](/api-reference/media/), in the order they show |
| `channel_text` | object | No | Own text for some channels: `{ "<channel id>": "text" }`. Other channels use `text`. |
| `settings` | object | No | Network settings by channel: `{ "<channel id>": { "first_comment": "..." } }` |
| `thread` | list | No | Up to 24 posts after the first, each `{ "text": "...", "media_ids": [] }` or a plain string |
| `campaign_id` | string or null | No | A campaign from [`GET /campaigns`](/api-reference/campaigns/) |

### Modes

| `mode` | What happens |
| - | - |
| `draft` | Saved on the calendar at `publish_at`. Nothing goes out. Network checks wait until you schedule it. |
| `schedule` | Goes out at `publish_at`. The time must be in the future. |
| `now` | Goes out right away. `publish_at` is ignored. |
| `queue` | Takes the next free time in the workspace's queue (**Settings**, **Queue**) |

`publish_at: "best"` picks the next of the workspace's best hours, at least 30 minutes from now. It needs enough results to know them. Until then you get `There aren't enough results yet to know the best times. Send a time, or use mode queue.`

<Aside type="note">
In a brand that needs approval, a post from an editor's key goes to `review` and waits there for approval. The answer's `status` tells you which one happened.
</Aside>

## What gets checked

Before a post is scheduled, Capybaroar checks it for every channel. A draft is checked only for its ids and files, so you can save half-done work.

- Every channel is in the workspace, from one brand, and not waiting to be reconnected.
- Every file is in the workspace's media library. Audio files can't be posted, and PDFs go to LinkedIn only.
- Each channel's text fits its network's limit, and required settings are there.
- Setting keys are ones the network takes, and select settings use one of their options.
- The network's own rules pass, like a picture for Instagram or one video for YouTube.
- The plan allows another post this month (Free allows 30).

The first problem stops the post and comes back as the error, like `Fernway Bakery: Instagram needs a picture or video`. The channel's name comes first, so you know which one to fix.

## Threads

On X, Threads, Bluesky and Mastodon, each item in `thread` goes out as a reply to the post before it. Channels on other networks post only the first part. Each part must fit the network's limit.

## Errors

| Status | Message |
| - | - |
| 400 | `channel_ids is required` |
| 400 | `publish_at is required when mode is schedule` |
| 400 | `Pick a time in the future` |
| 400 | `Pick channels from one brand` |
| 400 | `<channel>: <reason>` from a network check |
| 400 | `Your plan allows 30 scheduled posts a month. Upgrade to schedule more.` |
| 400 | `Add time slots to your queue in Settings first` |
| 400 | `That campaign belongs to another brand` |

See [Errors and limits](/api-reference/errors-and-limits/#posts) for the full list.
