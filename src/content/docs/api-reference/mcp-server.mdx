Capybaroar's MCP server lets an AI app use the same actions as the REST API. Claude, ChatGPT, Cursor and other MCP clients connect to it. Most people only need the setup steps in [Use Capybaroar from Claude, ChatGPT or Cursor](/ai/mcp/). This page is for building or debugging a client.

## Addresses

| Address | Sign-in | For |
| - | - | - |
| `https://app.capybaroar.com/api/mcp` | `Authorization: Bearer cbr_...`, or an OAuth sign-in | Claude, Claude Code, and any client that sends a header |
| `https://app.capybaroar.com/api/mcp/cbr_your_key` | The key in the address | Apps that only take a link, like ChatGPT's developer mode and Cursor |

Without a sign-in, the first address answers `401` with a `WWW-Authenticate` header that points to Capybaroar's sign-in, so Claude can start OAuth by itself. The person signs in, picks a workspace and presses **Allow**.

## Transport

The server speaks JSON-RPC 2.0 over plain HTTP `POST`. This is MCP's Streamable HTTP without sessions or event streams. Each request is answered on its own, so a restart on our side never drops a session. `GET` and other methods answer `405` with `Send MCP messages with POST`.

Protocol versions: `2025-11-25`, `2025-06-18`, `2025-03-26` and `2024-11-05`. A client that asks for one of these gets it back. Any other gets the newest.

## Start a session

<Tabs>
  <TabItem label="Request">

```bash
curl https://app.capybaroar.com/api/mcp \
  -H "Authorization: Bearer cbr_your_key" \
  -H "Content-Type: application/json" \
  -d '{ "jsonrpc": "2.0", "id": 1, "method": "initialize", "params": { "protocolVersion": "2025-06-18" } }'
```

  </TabItem>
  <TabItem label="Response">

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": "2025-06-18",
    "capabilities": { "tools": { "listChanged": false } },
    "serverInfo": { "name": "capybaroar", "title": "Capybaroar", "version": "1.0.0" },
    "instructions": "Capybaroar schedules posts to social channels from one calendar.\nCall list_channels first and only use the channel ids it returns. Respect each channel's character_limit and required settings.\nSave posts as drafts unless the user clearly asks to schedule or publish them.\nSend times as ISO 8601 with an offset. The workspace time zone is America/New_York.\nNever invent facts, numbers, quotes or customer names."
  }
}
```

  </TabItem>
</Tabs>

The `instructions` tell the AI how to use Capybaroar well, with your workspace's time zone filled in.

## Methods

| Method | Answer |
| - | - |
| `initialize` | The protocol version, the server's name and the instructions |
| `ping` | `{}` |
| `tools/list` | Every tool with its input schema. See [MCP tools](/api-reference/mcp-tools/). |
| `tools/call` | Runs a tool. The result is one text item holding the tool's JSON answer. |
| `resources/list` | An empty list |
| `prompts/list` | An empty list |

Notifications, like `notifications/initialized`, need no answer. A body with only notifications gets `202 Accepted` and no body.

## Call a tool

```bash
curl https://app.capybaroar.com/api/mcp \
  -H "Authorization: Bearer cbr_your_key" \
  -H "Content-Type: application/json" \
  -d '{ "jsonrpc": "2.0", "id": 2, "method": "tools/call", "params": { "name": "next_queue_slot", "arguments": {} } }'
```

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{ "type": "text", "text": "{\"publish_at\":\"2026-11-20T14:00:00.000Z\"}" }],
    "isError": false
  }
}
```

When a tool can't do what was asked, the answer is still a result, with `isError: true` and the message as its text. The AI can read the message and fix its request:

```json
{ "jsonrpc": "2.0", "id": 3, "result": { "content": [{ "type": "text", "text": "publish_at is required when mode is schedule" }], "isError": true } }
```

## Batches

A body can be a list of up to 25 messages. Each one counts against the key's 120 requests a minute. A list over 25 is refused whole with `Send up to 25 messages in a batch`.

## JSON-RPC errors

| Code | Message | When |
| - | - | - |
| `-32700` | `Parse error` | The body isn't valid JSON |
| `-32600` | `Invalid request` | Not a JSON-RPC 2.0 message, or an empty batch |
| `-32600` | `Send up to 25 messages in a batch` | A batch over 25 |
| `-32601` | `Method not found: <method>` | A method the server doesn't have |
| `-32602` | `Unknown tool <name>` | A tool that isn't listed |

Sign-in and rate-limit errors come back as HTTP errors in the [REST API's shape](/api-reference/errors-and-limits/), before any message runs.

## What each app sees

Every tool is listed for keys and for apps that sign in. The Claude directory app, signed in through claude.ai, leaves out `generate_media` and `get_generation`, following the directory's rules. ChatGPT and other apps that sign in keep every tool. Apps that sign in also see an OAuth `securitySchemes` entry on each tool.

<Aside type="note">
Tools run as the person who signed in, with their role and brands, and every post goes through the app's checks. An editor's AI can't do more than the editor.
</Aside>
